# 音声の入口の手順書

音声の入口は、ボタンを押して話しかけると、聞き取った言葉を、その言葉を受け付ける機能に渡す仕組みです（機能の名前は `voice`）。
入口は `src/osekkai/voice/` にあります。ほかの機能は、受け付ける言葉を入口に登録して使います。

この手順書は、保護者が設定を書くときと、開発者が機能から言葉を受け取るときに見るものです。

## 1. 何をするか

1. ボタンを押すと、ロボットがうなずき、LCD に「ｷｲﾃﾙﾖ」が出て「なあに？」と話します
2. 録音の間は LED が点きます。録音は設定の長さ（既定は 5 秒）です
3. LCD に「ｶﾝｶﾞｴﾁｭｳ」が出て、実機の中で声を文字にします（外には送りません）
4. 言葉に合う語句を登録した機能に渡します。どれにも合わなければ、受け手（おしゃべりの機能など）に渡します。受け手もなければ「ごめんね、まだ わからないんだ」と話します
5. 聞き取れなかったときは「ごめんね、きこえなかった。もういちど ボタンを おして はなしてね」と話します

そのほかの決まり:

- 聞ける時間帯の外（既定は 21 時 30 分〜7 時）と、時刻が確かでないときは、LCD に「ｵﾔｽﾐ ｼﾞｶﾝ」を出して「いまは ねる じかんだよ」と話します。聞き取りはしません
- おやすみモード（静かな状態）の間は、ボタンを押しても何もしません
- 起動してすぐは、聞き取りの準備（モデルを読む）に時間がかかります。その間に押すと「ちょっと まってね。じゅんび しているよ」と話します
- マイクやモデルがなくて使えないときは「いまは おはなし できないんだ」と話します
- 聞いている間にもう一度押しても、その押下は使いません
- 優先度の高い機能（日課の声かけなど）が声や画面を使うときは、聞いている途中でもやめて、その機能に譲ります

## 2. 設定の書き方

設定は、基盤と同じ設定ファイル `~/.config/osekkai/config.yaml` の `voice:` の節に書きます。
見本（[`config/osekkai.example.yaml`](../config/osekkai.example.yaml)）の `voice:` の節は既定値です。そのままで動きます。
設定を変えたら、ロボットを起動し直します。設定は起動のときに読みます。

```yaml
voice:
  enabled: true
  mic_device: "plughw:CARD=U0x46d0x825,DEV=0"
  listen_seconds: 5.0
  model: base
  hours: ["07:00", "21:30"]
  follow_up_seconds: 30.0
  recognizer: whisper     # 実機では whisper にする（見本は auto）
  max_gain: 20.0
```

| 項目 | 既定値 | 意味 |
| --- | --- | --- |
| `enabled` | `true` | `false` にすると入口は開始しません。ボタンの押下はほかの機能に任せます |
| `mic_device` | `"plughw:CARD=U0x46d0x825,DEV=0"` | マイクの名前。実機で `arecord -L` を実行して出る名前を書きます（既定は Logicool C270） |
| `listen_seconds` | `5.0` | 1 回の録音の長さ（秒、2〜15） |
| `model` | `base` | 聞き取りのモデルの大きさ（`base` か `small`）。`small` は正しく聞き取れますが、文字にするのが遅くなります。初期設定（provision）が置くのは `base` だけなので、`small` にするときは `~/.local/share/osekkai/models/faster-whisper-small/` に自分で置きます（置かないと self-check がだめになり、版が戻ります） |
| `hours` | `["07:00", "21:30"]` | 聞ける時間帯（始め、終わり）。始めは含み、終わりは含みません。始めが終わりより後なら、日をまたぐ帯です |
| `follow_up_seconds` | `30.0` | 続けて聞くの待ちの長さ（秒、5〜120）。この間にボタンを押すと、同じ機能に続けて話せます |
| `recognizer` | `auto` | 聞き取りの選び方。`whisper`（実機の聞き取り）、`typed`（端末で打った文字）、`auto`（faster-whisper があれば実機の聞き取り、なければ打った文字） |
| `max_gain` | `20.0` | 小さい声を持ち上げる倍率の上限（1〜50）。雑音まで大きくなるときは小さくします |

### 時刻は引用符で囲む

時刻は `"07:00"` のように、引用符で囲みます。秒（`"07:00:00"`）とタイムゾーンは書けません。
始めと終わりを同じにすることはできません。止めたいときは `enabled: false` にします。

### 実機では `recognizer: whisper` にする

見本は、開発 PC でも動くように `auto` です。
`auto` のままだと、実機に faster-whisper が入っていないときに打った文字の聞き取りになり、self-check の項目が飛ばしたになるので、気づけません。
実機の設定ファイルでは `recognizer: whisper` にします。そうすると、マイクやモデルがないときに self-check が「だめ」になります。

### 誤りがあるとき

設定に誤りがある（範囲の外、時刻の書き方の誤りなど）と、入口は開始しません。ほかの機能は動きます。
誤りの場所（キーのパス）と理由がログと self-check の `core.config` に出ます。値は出しません。

## 3. 実機に入れる順番

聞き取りのモデル（`faster-whisper-base`）は、実行中に取りに行きません。初期設定（provision）で、実機の
`~/.local/share/osekkai/models/faster-whisper-base/` に置きます（`model.bin`・`config.json`・`tokenizer.json`・`vocabulary.txt`）。

1. 音声の入口を初めて含む版を入れる **前に**、`rover-deploy provision` を実行して、モデルを置きます（約 148 MB。[`docs/deploy.md`](deploy.md) の 3 章）
2. 実機の設定ファイルの `voice:` の節に `recognizer: whisper` と書き、`mic_device` を実機のマイクの名前に合わせます
3. 音声の入口を含む版を `rover-deploy deploy` で入れます。版の準備で faster-whisper も入ります（extras の `pi,voice`。pip に前より時間がかかります）
4. self-check で `voice.mic` と `voice.model` が「よい」になることを確かめます
5. ロボットが止まっているときに、聞き取りの確認のコマンド（下の 5 章）で、声が文字になることを確かめます

## 4. 機能から言葉を受け取る（開発者へ）

機能は `osekkai.voice.api` だけを読みます。聞き取りのアダプタは読みません。

```python
import threading

from osekkai.voice.api import Heard, listen_again, register_words


class DarumaFeature:
    ...

    def run(self, stop: threading.Event) -> None:
        registration = register_words(
            "daruma",  # 機能の名前
            0,  # 優先度（大きいほど先に判定する）
            ("だるまさん", "だるまさんがころんだ", "だるまさんが転んだ"),
            self._on_heard,
            alive=lambda: not stop.is_set(),
        )
        try:
            while not stop.is_set():
                ...  # 自分の仕事
        finally:
            registration.remove()

    def _on_heard(self, heard: Heard) -> None:
        # すぐに戻る。重い仕事は自分のスレッドに渡す
        self._inbox.put(heard)
```

決まり:

- `run(stop)` の始めに登録し、`alive=lambda: not stop.is_set()` を渡し、`finally` で `remove()` します。例外で止まっても、止める旗が立っても、登録は使われなくなります
- `alive` は登録表のロックの中で呼びます。軽い確かめだけにし、登録の口を呼びません
- 言葉が来たときに呼ばれる口（handler）は、すぐに戻ります。重い仕事は自分のスレッドに渡します
- 判定は「言葉に語句が含まれるか」です。ひらがなとカタカナ、空白、句読点、のばす音（ー）の違いは気にしません。漢字はかなにしないので、かなと、聞き取りが出しそうな漢字の形の両方を登録します（例: 「だるまさんがころんだ」「だるまさんが転んだ」）
- いくつかの機能の語句に合うときは、優先度の高い方、同じなら先に登録した方に渡します
- `heard.text` は聞き取った言葉です。ログや記録に出しません。`heard.follow_up` は、続けて聞いた言葉なら `True` です
- 言葉を受け取った後に、続けて聞いてほしいときは `listen_again("daruma")` を呼びます。`follow_up_seconds` の間にボタンを押すと「うん、なあに？」と聞き、振り分けずにその機能に渡します。押されなければ、黙って待ちを終えます。`listen_again` は、返事を話し終えた後に呼びます
- 言葉を受け取ってから自分の振る舞い（あそびなど）が終わるまでは、声・画面と一緒にボタンも借りておきます。ボタンを借りていないと、押下は入口に届き、入口（優先度 55）が資源を取り上げて聞き取りを始めます
- どの語句にも合わない言葉を受け取りたい機能（おしゃべりなど）は、`register_fallback(owner, handler, alive=...)` で受け手になります。受け手は 1 つだけです。生きている受け手があると `FallbackTaken` になります
- 語句なし・空の語句は `ValueError` です

## 5. 聞き取りの確認のコマンド（開発者へ）

実機のマイクとモデルで 1 回だけ録音して文字にし、聞き取った言葉とかかった時間を端末に出します。
ロボットのサービスが動いているときは、録音せずに終えます（終了コード 75）。サービスを止めてから実行します。

```sh
python -m osekkai.voice --listen-once               # 設定の listen_seconds だけ録音する
python -m osekkai.voice --listen-once --seconds 3   # 録音の長さを指定する
```

- 聞き取った言葉は標準出力にだけ出します。ログ（journal）には出しません
- 設定ファイルがないときは既定値で試します。`--config PATH` で設定ファイルを指定できます
- 準備ができない（マイクかモデルがない）・聞き取りに失敗したときは、理由を出して終了コード 1 で終えます

## 6. PC で試す（ハードなし）

開発 PC では、ハードなしの実行で試せます。faster-whisper はないので、`recognizer: auto` のままなら、端末で打った文字を聞き取った言葉にします。

```sh
python -m osekkai --fake-hardware
```

端末で `だるまさん しよう` と打って Enter を押すと、ボタンを押して「だるまさん しよう」と話したことになります。
Enter だけを押すと、聞き取れなかったときの流れになります。

## 7. 個人の情報の扱い

- 声は実機の中だけで文字にします。外には送りません
- 録音はファイルに書きません
- 聞き取った言葉・登録した語句・話す言葉・LCD の文字は、ログ・記録・self-check に出しません。ログには決まった文言・機能の名前・例外の型の名前・かかった時間だけを出します
- 受け取った言葉の扱いは、受け取った機能の責任です

## 8. self-check の項目

| 項目 | よい | だめ | 飛ばした |
| --- | --- | --- | --- |
| `voice.mic` | `arecord -L` の一覧に `mic_device` の名前がある | 「マイクが見つからない」 | 打った文字の聞き取り・無効・入口の設定を使えない、のとき。ロボットが動いていてハードに触れないときも |
| `voice.model` | モデルの置き場所に 4 つのファイルがそろっている | 「聞き取りのモデルがない」 | 打った文字の聞き取り・無効・入口の設定を使えない、のとき |

- 飛ばしたの理由「打った文字の聞き取り」は、`recognizer: typed` のときと、`auto` で faster-whisper がないときに出ます。開発 PC と CI ではこれになります
- 実機でこの理由が出たら、設定の `recognizer` を `whisper` にします（2 章）
