# 朝と夜のお話の手順書

朝と夜のお話は、寝る前と朝に、ロボットから天気と、子どもの好きなものの短い豆知識を話す機能です（機能の名前は `talk`）。
夜はあしたの天気を、朝は今日の天気を話します。豆知識は、保護者が設定に書いた好きなものから 1 つを選び、Claude（Anthropic の会話の AI）に作らせます。
機能は `src/osekkai/features/talk/` にあります。

この手順書は、保護者が設定を書き、外に送るものを確かめ、実機で確かめるときに見るものです。

## 1. 何をするか

お話は、日課（[`docs/routine.md`](routine.md)）の予告に続けて話します。日課が無効なときは話しません。
予告の時刻は、日課の時刻のタスクの時刻から、予告の早さ（`notice_min`、既定は 10 分）だけ前の時刻です。タスクに予告の言葉（`notice`）がなくても、この時刻を使います。

### 夜のお話

1. 寝るタスク（`sleep: true`）の予告の時刻になり、日課が予告を言い終えたら、続けて話します。予告の言葉がなければ、予告の時刻に話します
2. 日課が声かけや予告の最中なら、終わるのを待ちます
3. 寝るタスクを始める時刻までに話し始められなければ、その日の夜のお話はしません。寝るタスクが始まった後・おやすみモードの間も話しません
4. 今日の種類の日（平日・休日）に寝るタスクがなければ話しません

### 朝のお話

朝の最初のタスクは、その日の時刻のタスク（`at` のタスク）のうち、寝るタスクを除いて最も早いものです。

1. 最初のタスクの予告の時刻が起床時刻と同じか後なら、その予告に続けて話します（予告の言葉がなければ、予告の時刻に話します）
2. 予告の時刻が起床時刻より前（おやすみモードの間）なら、予告の時刻には話さず、最初のタスクが終わった後（できた・スキップ・中断のどれでも）に話します
3. 予告に続けて話せないまま最初のタスクの時刻を過ぎたら、そのタスクが終わった後に話します
4. 最初のタスクが終わってから 60 分たっても話し始められなければ、その日の朝のお話はしません
5. 起床時刻（おやすみモードが終わる時）には、これまでどおり声を出しません

### 話すこと

| 順 | 夜 | 朝 |
| --- | --- | --- |
| 始まり | `{name}、おやすみの まえの おはなし だよ` | `おはよう、{name}。きょうの おはなし だよ` |
| 天気 | あしたの天気・いちばん高い気温と低い気温・一言 | 今日の天気・いちばん高い気温と低い気温・一言 |
| 豆知識 | 寝る前に合う、落ち着いたお話 | 明るく、楽しい気持ちになれるお話 |
| 終わり | `あしたも たのしみだね。おやすみ、{name}` | `きょうも いちにち がんばろうね、{name}` |

- `{name}` には設定の呼び名（`call_name`）が入ります。空なら「きみ」です
- 天気の話の例: 「あしたは はれ だよ。いちばん あつい ときは 18ど、いちばん さむい ときは 9ど だよ」
- 一言は、降る確率が `rain_percent` 以上なら「かさを もって いこうね」、いちばん低い気温が `cold_below` より低ければ「うわぎを きて いこうね」、いちばん高い気温が `hot_at_or_above` 以上なら「おみずを たくさん のもうね」です
- 大雨・大雪・強い風・雷・波の注意報か警報が出ていると、怖がらせない言葉で知らせ、「おうちの ひとと いっしょに きを つけようね」と添えます。乾燥・濃霧・霜などは話しません
- 豆知識は 2 文・120 文字までです。絵文字や記号は話しません
- 天気の話の間は、LCD に「ｱｼﾀ ﾊﾚ 18/9」（夜）や「ｷｮｳ ｸﾓﾘ 12/5」（朝）のように出ます。そのほかの間は「ｵﾊﾅｼ」が出ます
- 1 回のお話は、おおむね 60 秒以内です。話し終えたら、声と画面を返して待機画面に戻ります

### 話せないとき・やめるとき

- 天気が取れない（インターネットにつながらない・古い予報しかない）ときは、豆知識だけを話します。注意報だけが取れないときは、注意報に触れずに天気を話します
- 豆知識が作れない（鍵がない・時間切れ・断られた）ときは、天気だけを話します
- どちらもないときは、始まりの言葉を言わず、夜は「きょうも たのしかったね。おやすみ なさい」、朝は「おはよう。きょうも いちにち たのしもうね」だけを話します
- 天気と豆知識は前もって用意し、話す時は 5 秒だけ待ちます。間に合わなかった部分は省きます
- 日課が声を求めたとき、ボタンを押して話しかけたとき、ラジコンなど優先度の高い機能が声を使うとき、おやすみモードに入ったときは、話している文を言い終えたところでやめます。その回は話したことにして、続きは話しません
- ほかの機能が声を使っている間は、終わるのを待ちます。上の締め切り（夜は寝るタスクの時刻、朝は最初のタスクが終わってから 60 分）を過ぎたら、その回は話しません
- 時刻が確かでない間（時刻の同期の前）は話し始めません。話している間、モーターは動かしません
- 夜と朝のお話は、それぞれ 1 日に 1 回までです。起動し直しても、その日にもう話したお話はもう一度話しません
- おしゃべり（`conversation`）の 1 日の回数と時間帯には数えません

## 2. 設定の書き方

設定は、基盤と同じ設定ファイル `~/.config/osekkai/config.yaml` の `talk:` の節に書きます。
見本（[`config/osekkai.example.yaml`](../config/osekkai.example.yaml)）の `talk:` の節は次のとおりで、既定は無効です。
設定を変えたら、ロボットを起動し直します。設定は起動のときに読みます。

```yaml
talk:
  enabled: false
  call_name: ""                 # 始まりと終わりの言葉の呼び名。外には送らない。空なら「きみ」
  night: true                   # 寝るタスクの予告の後に話す
  morning: true                 # 朝の最初のタスクの予告の後（または、そのタスクの後）に話す
  # location: {latitude: 35.68, longitude: 139.69}   # 0.1 度に丸めて天気の問い合わせに使う
  # warning_area: {office: "130000", city: "1311300"} # 気象庁の地域のコード（docs/talk.md）
  topics: []                    # 好きなもの（例: ["きょうりゅう", "でんしゃ"]）
  rain_percent: 50              # 降る確率がこれ以上なら傘を勧める（1〜100）
  cold_below: 10                # いちばん低い気温がこれより低ければ上着を勧める（-20〜30）
  hot_at_or_above: 30           # いちばん高い気温がこれ以上なら水を勧める（20〜45）
  fetch_timeout_seconds: 20.0   # 天気と豆知識の問い合わせの時間切れ（秒、5〜60）
```

使うときの書き方の例です（場所とコードは東京駅のあたりの見本の値です。家の近くの値に替えます）。

```yaml
talk:
  enabled: true
  call_name: ""
  location: {latitude: 35.68, longitude: 139.69}
  warning_area: {office: "130000", city: "1311300"}
  topics: ["きょうりゅう", "でんしゃ", "どうぶつ"]
```

| 項目 | 既定値 | 意味 |
| --- | --- | --- |
| `enabled` | `false` | `true` にすると、お話をします |
| `call_name` | `""` | 始まりと終わりの言葉の `{name}` に入る呼び名。外には送りません（5 章）。空なら「きみ」 |
| `night` | `true` | 夜のお話をするか |
| `morning` | `true` | 朝のお話をするか |
| `location` | なし | 天気を調べる場所（緯度 `latitude` は -90〜90、経度 `longitude` は -180〜180）。なければ天気の話をせず、豆知識だけを話します |
| `warning_area` | なし | 注意報と警報を調べる地域（気象庁のコード。3 章）。なければ注意報と警報に触れません。`location` がないときは使いません |
| `topics` | `[]` | 好きなもの（1 つ 20 文字まで、20 個まで）。空なら豆知識を話さず、天気の話だけを話します |
| `rain_percent` | `50` | その日の雨か雪の降る確率がこれ以上なら、傘を勧めます（1〜100） |
| `cold_below` | `10` | いちばん低い気温がこれより低ければ、上着を勧めます（度、-20〜30） |
| `hot_at_or_above` | `30` | いちばん高い気温がこれ以上なら、水を勧めます（度、20〜45） |
| `fetch_timeout_seconds` | `20.0` | 天気と豆知識の問い合わせを待つ長さ（秒、5〜60）。過ぎたら、使えなかったものとして省きます |

- 気象庁のコードは `"130000"` のように、必ず引用符で囲みます。引用符がないと数として読まれ、設定の誤りになります（YAML は、先頭の 0 を消したり、8 進の数として読んだりします）
- 好きなものは、ひらがなで書くと、Claude が 4 歳向けの言葉で話しやすくなります。空の項目は書けません
- 好きなものに呼び名を入れると、設定の誤りになります（呼び名を外に送らないため）
- 現在地・好きなもの・呼び名は個人の情報です。見本の値は替えずに、実機の設定ファイルにだけ書きます
- 現在地と好きなものの両方がないと、お話をしません（self-check の `talk.setup` に「話すことがない」と出ます）
- 設定に誤り（範囲の外、コードの書き方の誤りなど）があると、お話は開始しません。ほかの機能は動きます。誤りの場所（キーのパス）と理由はログに、誤りの件数は self-check の `core.config` に出ます。値は出しません
- 豆知識には、おしゃべりと同じ Claude の鍵（`~/.config/osekkai/env`）を使います。置き方は [`docs/conversation.md`](conversation.md) の 2 章を見ます。会話のライブラリは、`rover-deploy deploy` の版の準備で入ります

## 3. 現在地と気象庁のコードの調べ方

### 現在地（`location`）

天気の問い合わせには、緯度と経度を 0.1 度（約 10 km）に丸めて送ります。家の細かい場所は要りません。
地図のアプリで、家の近くの駅や市区町村の役所の場所を開き、緯度と経度を小数 2 けたほどで書きます。家そのものの場所は書かなくてかまいません。

### 注意報と警報の地域（`warning_area`）

気象庁の地域の一覧 <https://www.jma.go.jp/bosai/common/const/area.json> から、2 つのコードを調べます。

| 項目 | けた | 一覧の中の場所 | 見本 |
| --- | --- | --- | --- |
| `city` | 7 けた | `class20s`（市区町村）のキー | `"1311300"`（渋谷区） |
| `office` | 6 けた | `offices`（府県予報区）のキー。`city` からたどる | `"130000"`（東京都） |

`city` の `parent` は `class15s`、その `parent` は `class10s`、その `parent` が `office` です。
見本では、`1311300`（渋谷区）→ `130011`（２３区西部）→ `130010`（東京地方）→ `130000`（東京都）とたどります。

次のコマンドで、市区町村の名前からコードを調べられます（一覧を丸ごと取って、手元で探します。名前は外に送りません）。
`渋谷区` を自分の市区町村の名前に替えます。

```sh
curl -fsS https://www.jma.go.jp/bosai/common/const/area.json | python3 -c '
import json, sys
area = json.load(sys.stdin)
for code, city in area["class20s"].items():
    if city["name"] == sys.argv[1]:
        office = area["class10s"][area["class15s"][city["parent"]]["parent"]]["parent"]
        print("office:", office, area["offices"][office]["name"], " city:", code)
' 渋谷区
```

- 同じ名前の市区町村（例: 府中市）は何行も出ます。`office` の名前（都道府県など）で選びます
- 北海道・沖縄・鹿児島などは、府県予報区が 1 つの道県の中で分かれています。上のコマンドでたどった `office` を使います
- 名前で見つからないときは、一覧を開いて `class20s` の `name` を探します（例: 札幌市は区に分かれず「札幌市」の 1 つです）
- コードは ASCII の数字で、引用符で囲んで書きます

## 4. self-check の項目

`python -m osekkai --self-check`（実機では `rover-deploy self-check`）に、`talk.setup` と `talk.weather` が出ます。
どちらも「だめ」にはしません（ネットワークの都合や設定の選び方で、版を戻さないため）。「よい」に理由を添えて知らせます。

### `talk.setup`（設定で何を話せるか）

外には問い合わせません。理由は 1 つだけ、上の行ほど大事なものが出ます。

| 結果 | 理由 | 直し方 |
| --- | --- | --- |
| よい | （なし） | 天気と豆知識を話せます |
| よい | 日課がないので話さない | お話は日課の予告に続くので、日課を有効にします（`routine:` の節） |
| よい | 話すことがない | `location` か `topics` を書きます |
| よい | 鍵がないので天気だけ | Claude の鍵かライブラリがないので、豆知識を話しません。鍵を置きます（[`docs/conversation.md`](conversation.md) の 2 章）。開発 PC ではこれになります |
| よい | 鍵がないので決まった言葉だけ | 好きなものだけを書いていて、鍵かライブラリがないときです。豆知識を取れないので、決まった短い言葉だけを話します。鍵を置くか、`location` を書きます |
| よい | 天気だけ | `topics` が空です。天気だけでよければ、そのままにします |
| よい | 豆知識だけ | `location` がありません。豆知識だけでよければ、そのままにします |
| 飛ばした | 無効 | 設定で `enabled: false` のときです |
| 飛ばした | 設定を使えない | 設定ファイルがないか、誤りがあるときです。`core.config` を見ます |

### `talk.weather`（天気と注意報を取れるか）

天気（Open-Meteo）と、`warning_area` を書いたときは注意報（気象庁）に、1 回ずつ問い合わせます（1 回 10 秒まで）。取れた値は見ずに捨てます。
外に問い合わせるので、ロボットのサービスを止めて、手で self-check を行ったときだけ確かめます。サービスが動いているとき（配置の後の確かめなど）と `--no-hardware` のときは「飛ばした（ほかが動いている）」になります。

```sh
systemctl --user stop osekkai.service
~/osekkai-rover/current/.venv/bin/python -m osekkai --self-check
systemctl --user start osekkai.service
```

| 結果 | 理由 | 直し方 |
| --- | --- | --- |
| よい | （なし） | 天気（と注意報）を取れます |
| よい | 天気を取れない | 実機がインターネットにつながっているかを確かめます。`location` の緯度と経度の順も確かめます |
| よい | 注意報を取れない | `office` と `city` のコードを確かめます（3 章）。気象庁のデータの形が変わったときもこれになります |
| よい | 天気を取れない、注意報を取れない | 両方とも取れないときです。まずインターネットのつながりを確かめます |
| 飛ばした | 現在地がない | `location` がないときです |
| 飛ばした | 無効 | 設定で `enabled: false` のときです |
| 飛ばした | 設定を使えない | 設定ファイルがないか、誤りがあるときです。`core.config` を見ます |

- 理由には、現在地・好きなもの・鍵・天気の値を出しません

## 5. 外に送るもの・送らないもの

外への問い合わせは、どれも HTTPS です。ほかのサイトを開くときと同じく、家のインターネットのアドレス（IP アドレス）は相手に見えます。

| 送り先 | 送るもの | 送らないもの |
| --- | --- | --- |
| Open-Meteo（天気） | 0.1 度に丸めた緯度と経度（約 10 km の粗さ）と、決まった項目の名前 | 呼び名・好きなもの・細かい現在地。鍵は要りません |
| 気象庁（注意報・警報） | 府県予報区のコード（`office`。URL に入ります） | 呼び名・好きなもの・現在地。市区町村のコード（`city`）は、取った都道府県の分のデータからロボットの中で探すのに使い、送りません |
| Claude（豆知識） | 豆知識の決まりの文（子ども向けの話し方の決まり）、選んだ好きなもの 1 つ、夜か朝かの別、月と季節（例: 「11がつ、あき」） | 呼び名・現在地・天気・日付の日。おしゃべりのやりとり |

残すもの・残さないもの:

- 実機に残すのは、日付ごとの夜と朝の結果（話した・諦めた）と、直前に選んだ好きなものの hash（16 文字）だけです（`~/.local/state/osekkai/talk/record.json`。7 日より古い日は消します）。好きなものの文字は残しません
- 天気の値と豆知識の言葉は記憶の中にだけ置き、話し終えたら捨てます。豆知識の声も残しません
- 現在地・天気の値・好きなもの・豆知識・呼び名・鍵は、ログ・self-check の結果・記録に出しません。ログには、決まった文言と、夜か朝か（`NIGHT`・`MORNING`）・結果の種類・失敗の種類・かかった時間だけを出します
- 記録が読めない（壊れたなど）日は、その日はもう話したものとして扱います（同じお話が何度も流れないため）
- Claude の費用は、豆知識 1 回で約 1 円ほどで、1 日に多くて 2 回です。Anthropic の側でのデータの扱いは、Anthropic の利用規約とプライバシーの方針に従います

## 6. 試しにお話をさせる

時刻を待たずに、夜か朝のお話を 1 回話させられます。その日に話した記録と、直前に選んだ好きなものの記録は変わりません。

```sh
python -m osekkai.features.talk --try night|morning [--fake-hardware] [--config PATH]
```

| 引数 | 意味 |
| --- | --- |
| `--try night` / `--try morning` | 夜のお話（あしたの天気）か、朝のお話（今日の天気）か |
| `--fake-hardware` | ハードなしで、端末に画面と声を出す（PC で確かめる）。外には問い合わせず、決まった天気（はれ、18/9）と、決まった豆知識（「<好きなもの>には ふしぎな ことが いっぱい あるんだって」）を使います |
| `--config PATH` | 別の設定ファイルを使う |

実機では、ロボットのサービスを止めてから動かします。子どもが使っていない時間に行います。

```sh
systemctl --user stop osekkai.service          # 1. サービスを止める
cd ~/osekkai-rover/current
.venv/bin/python -m osekkai.features.talk --try night   # 2. 夜のお話を試す
systemctl --user start osekkai.service         # 3. 終わったらサービスを起動する
```

- 天気と豆知識は、その場で取ります。用意を `fetch_timeout_seconds` まで待つので、話し始めるまで時間がかかることがあります。実機では外に問い合わせます（5 章）
- 話し終えると、結果を 1 行出して終了コード 0 で終わります

  | 出る行 | 意味 |
  | --- | --- |
  | はなしました | 最後まで話した |
  | おやすみモードなので はなしませんでした | おやすみモード（静かな状態）だった。用意もしません。おやすみモードのままサービスを止めたときも、起床時刻を過ぎて動かすまではこれになります |
  | 中断 | 話している途中で、ほかの機能が声を求めたか、おやすみモードに入った。または Ctrl+C で止めた |
  | はなせませんでした | 思いがけない失敗 |

- ロボットのサービスが動いているときは「ロボットが動いています。止めてから試してください」と出て、終了コード 75 で終わります（ハードに触りません）
- お話が無効（`talk.enabled: false`）のときは「お話が無効になっています（talk.enabled）」と出て、終了コード 1 で終わります。試すときも `enabled: true` にします
- 設定に誤りがあるときと、`--fake-hardware` なしで実機のアダプタを読み込めないとき（PC など）も、理由を出して終了コード 1 で終わります
- 試しでは、日課の状況（予告・おやすみの時刻）は見ません。日課が無効でも話します
- 基盤の起動の声（`core.startup_voice_hours` の間）は、試しでも流れます

PC では次のように試します。`--config` には、`talk:` の節で `enabled: true` と `location` か `topics` を書いた設定ファイルを渡します。

```sh
python -m osekkai.features.talk --try morning --fake-hardware --config ~/talk-try.yaml
```

## 7. 実機で確かめる

実機は子どもが毎日使っている 1 台です。試すのは、子どもが使っていない時間（声かけの予定がない時間）にします。
作業ブランチの版を入れて試したら、終わったら必ず普段の版に戻します（`rover-deploy back`。[`.kiro/steering/git-workflow.md`](../.kiro/steering/git-workflow.md)、[`docs/deploy.md`](deploy.md)）。

1. 開発 PC から、お話を含む版を入れます（`deploy/rover-deploy deploy <タグかブランチ>`）
2. 4 章のとおり、`talk.setup` が理由なしの「よい」、`talk.weather` が理由なしの「よい」になることを確かめます
3. 見本の応答を取り直します（下の「見本の応答の取り直し」）
4. 6 章のとおりサービスを止めて、`--try night` と `--try morning` を試し、次を確かめます
   - 始まりから終わりまでが 60 秒以内（時計で測ります）
   - 夜はあしたの、朝は今日の天気と気温を話し、LCD に「ｱｼﾀ …」「ｷｮｳ …」が出る。天気の話のほかの間は「ｵﾊﾅｼ」が出る
   - 豆知識が、設定の好きなものの 1 つについての短いお話になっている
   - 声の大きさが、いつもの声かけと同じくらい
5. 実機のネットワークを切って `--try night` を試すと、決まった短い言葉（「きょうも たのしかったね。おやすみ なさい」）だけを話し、終わる
6. 日課の予告に続けて話すことと、日課の声かけが遅れないことを確かめます。実機の記録を変えないよう、状態の置き場所を別のフォルダにして動かします
   - 試しの設定ファイル（実機の設定ファイル `~/.config/osekkai/config.yaml` を写して、朝の最初のタスクの時刻を今から 15 分ほど後にずらしたもの。例: `~/talk-try.yaml`）を作ります
   - サービスを止めて、状態の置き場所を `~/talk-try-state` にしてロボットを動かします

     ```sh
     systemctl --user stop osekkai.service
     cd ~/osekkai-rover/current
     XDG_STATE_HOME=~/talk-try-state .venv/bin/python -m osekkai --config ~/talk-try.yaml
     ```

   - 予告の後に続けて朝のお話を話し、タスクの時刻ちょうどに日課の声かけが始まることを確かめます
   - 夜のお話を確かめるときは、寝るタスクの時刻をずらします。寝るタスクが終わるとおやすみモードに入りますが、おやすみモードの状態も別のフォルダに残るので、普段のロボットは静かになりません
   - 終わったら Ctrl+C で止め、別のフォルダを消してから、サービスを起動します

     ```sh
     rm -rf ~/talk-try-state
     systemctl --user start osekkai.service
     ```

   - 別のフォルダにしたので、実機の記録（日課の結果と星・お話の 1 日に 1 回の記録・おやすみモードの状態・おしゃべりの回数）は変わりません。その代わり、試しの間は、星は 0 から数え、覚えた顔もない状態で動きます（見つけてあいさつは呼び名であいさつしません）
   - 設定ファイル（`--config` で渡したもの）・Claude の鍵（`~/.config/osekkai/env`）・声のキャッシュ・単一の実行のロックは、いつもの場所のままです。サービスが動いたままだと、ロックで「すでに動いています」（75）と出て終わります
7. ログ（`journalctl --user-unit=osekkai.service -b`）に、現在地・天気の値・好きなもの・豆知識・呼び名が出ていない
8. 普段の版に戻します（`deploy/rover-deploy back`）

### 見本の応答の取り直し

テスト（`tests/features/talk/test_talk_open_meteo.py`・`test_talk_jma_alerts.py`）は、`tests/features/talk/fixtures/` の見本の応答で読み方を確かめています。
気象庁の注意報・警報は、朝（05 時ごろ・11 時ごろ）と夕方（17 時ごろ）に出る報で形が違うことがあるので、それぞれの報を実機から取り直します。

- **見本には、家の場所の値を使いません。** 公開のリポジトリに入るためです。Open-Meteo は東京駅のあたり（35.7、139.7）、気象庁は東京都（`130000`）で取ります（Open-Meteo の応答には、問い合わせた緯度と経度が入ります）

```sh
curl -fsS 'https://api.open-meteo.com/v1/forecast?latitude=35.7&longitude=139.7&daily=weather_code,temperature_2m_max,temperature_2m_min,precipitation_probability_max&timezone=Asia%2FTokyo&forecast_days=2' -o open_meteo_forecast.json
curl -fsS https://www.jma.go.jp/bosai/warning/data/r8/130000.json -o jma_r8_tokyo_0500.json   # 05 時ごろの報の後に取る
```

- 気象庁のファイルは、報ごとに `jma_r8_tokyo_0500.json`・`jma_r8_tokyo_1100.json`・`jma_r8_tokyo_1700.json` のように名前を分けて、開発 PC の `tests/features/talk/fixtures/` に置きます。大きいときは、今の `jma_r8_tokyo.json` と同じく、テストで使う市区町村だけに減らします
- 置いたら、開発 PC で `pytest -q tests/features/talk` を行い、読み方が変わっていないことを確かめます。形が変わっていたら、アダプタを直します

## 8. 出典と利用の条件

お話の天気と注意報は、次のデータを使っています。

- **天気の予報**: Weather data by [Open-Meteo.com](https://open-meteo.com/)（[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)）
  - 非商用は無料で、鍵は要りません。1 日 1 万回までです（[利用の条件](https://open-meteo.com/en/terms)）。お話は 1 日に数回しか問い合わせません
  - 天気のコードを「はれ」「くもり」などの言葉に、気温を整数に直して話します
- **注意報・警報**: 出典：気象庁ホームページ（<https://www.jma.go.jp/bosai/warning/>）。注意報・警報のデータを加工して利用（市区町村を選び、種類を子ども向けの言葉に直して話します）
  - [気象庁ホームページについて](https://www.jma.go.jp/jma/kishou/info/coment.html)（公共データ利用規約）に従います
  - 公式の API ではないので、URL やデータの形は予告なく変わることがあります。そのときは注意報に触れずに天気を話し、self-check の `talk.weather` に「注意報を取れない」と出ます
- 見本の応答（`tests/features/talk/fixtures/`）も、同じ出典のデータです

利用の条件が変わったときは、この手順書と README の出典の表記を直します。
