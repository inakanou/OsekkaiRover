# 日課の手順書

日課は、決まった時刻に子どもへ声をかける機能です（機能の名前は `routine`）。
声かけをして、できたらボタンを押してもらい、ほめて星をためます。待機画面の右上に星の数（例: `★12`）が出ます。
寝るタスクが終わると、おやすみモードに入り、起床時刻まで静かにします。

この手順書は、保護者が設定を書くときと、困ったときに見るものです。

## 1. 設定の場所

日課の設定は、基盤と同じ設定ファイル `~/.config/osekkai/config.yaml` の `routine:` の節に書きます。

- 設定ファイルがないときは、起動のときに見本（[`config/osekkai.example.yaml`](../config/osekkai.example.yaml)）から作られます
- 見本の `routine:` の節は全部コメントです。そのままではタスクは 0 個で、日課は声をかけません（星だけが出ます）
- 子どもの呼び名・言葉・時刻は、この設定ファイルにだけ書きます。リポジトリには書きません
- 設定を変えたら、ロボットを起動し直します。設定は起動のときに読みます

## 2. 設定の書き方

見本の `# routine:` から下の行の頭の `# ` を消して、値を家の暮らしに合わせて直すのが簡単です。

```yaml
routine:
  call_name: ""            # 子どもの呼び名。言葉の {name} に入る。空なら「きみ」
  extra_holidays: []       # 追加の休日（例: ["2026-08-13", "2026-08-14"]）
  wake:                    # 起床時刻。書かなければ、その日の最初の時刻のタスクの時刻
    weekday: "06:30"
    holiday: "07:30"
  keep_days: 90            # 記録を残す日数（7〜3650）
  sleep_wait_min: 30       # 寝るタスクが、続いている声かけを待つ長さ（分、0〜55）
  tasks:
    - id: hamigaki_morning
      at: "07:00"
      call: "{name}、はみがきの じかんだよ"
      praise: "はみがき できたね"
      lcd: "ﾊﾐｶﾞｷ"
    - id: oyasumi
      at: "21:00"
      days: everyday
      call: "{name}、ねる じかんだよ"
      praise: "おやすみなさい"
      lcd: "ﾈﾙ ｼﾞｶﾝ"
      sleep: true
```

上の時刻と言葉は例です。

### 時刻は引用符で囲む

時刻は `"07:00"` のように、必ず引用符で囲みます。
引用符がないと、YAML が時刻を数として読むことがあります。引用符で囲むと確実です。
秒（`"07:00:00"`）とタイムゾーンは書けません。

### 節の全体の項目

| 項目 | 既定値 | 意味 |
| --- | --- | --- |
| `enabled` | `true` | `false` にすると日課は開始しません |
| `call_name` | `""` | 子どもの呼び名。言葉の中の `{name}` に入ります。空なら「きみ」 |
| `extra_holidays` | `[]` | 土日と祝日のほかに休日にする日（`"2026-08-13"` の形） |
| `wake.weekday`・`wake.holiday` | なし | 平日・休日の起床時刻。なければ、その種類の日の最初の時刻のタスク（寝るタスクは除く）の時刻 |
| `keep_days` | `90` | 記録を残す日数。古い記録は消します。星の数は減りません |
| `sleep_wait_min` | `30` | 寝るタスクの時刻にほかの声かけが続いているとき、その流れ（続きのタスクを含む）を待つ長さ（分、0〜55）。過ぎたら割り込みます。`0` なら時刻にすぐ割り込みます |
| `tasks` | `[]` | タスクの一覧 |

### タスクの項目

| 項目 | 既定値 | 意味 |
| --- | --- | --- |
| `id` | （必ず書く） | タスクの名前。英小文字で始め、英小文字・数字・`_` だけ。32 文字まで。ほかのタスクと重ねない |
| `at` | なし | 始める時刻（`"HH:MM"`） |
| `after` | なし | 前のタスクの `id`。そのタスクが終わったら始めます。`at` と `after` は、どちらか 1 つだけ書きます |
| `days` | `everyday` | `everyday`（毎日）、`weekday`（平日）、`holiday`（休日。土日・祝日・追加の休日） |
| `call` | （必ず書く） | 声かけの言葉 |
| `praise` | （必ず書く） | できたときにほめる言葉 |
| `lcd` | （必ず書く） | LCD の 1 行目に出す短い文字（16 文字まで）。半角のカナが確実です |
| `notice` | なし | 予告の言葉。`at` のタスクだけに書けます |
| `notice_min` | `10` | 予告を何分前に言うか（1〜120） |
| `ready` | なし | 準備の声かけ。書くと「準備の声かけ → ボタンが押されるまで待つ → 声かけ」の順になります |
| `remind_min` | `5` | 催促の間隔（分、1〜60） |
| `max_reminders` | `2` | 催促の回数の上限（0〜10） |
| `firm` | `false` | `true` なら割り込めるタスク。ほかのタスクの声かけ・催促・あとでの途中でも始まります |
| `sleep` | `false` | `true` なら寝るタスク。終わるとおやすみモードに入ります。`at` で始めます |

催促を上限まで行ってもボタンが押されないと、「あとで できたら ボタンを おしてね」と言って、30 分の間ボタンを受けます。
それでも押されなければ「スキップ」になります。

### 寝るタスクは、続いている声かけを待つ

寝るタスクの時刻になったとき、ほかの声かけ（おふろ → パジャマ → はみがき のような続きの流れ）がまだ進んでいれば、寝るタスクはその流れが終わるのを待ちます。
流れが終わったら、すぐに寝るタスクを始めます。
待つのは `sleep_wait_min`（既定は 30 分）までです。過ぎても流れが終わらなければ、今の声かけを「中断」にして寝るタスクを始めます（中断の後ろの続きのタスクは、その日は始めません）。
ほかの声かけがなければ、時刻にすぐ始めます。

### 寝るタスクは「毎日」にする

寝るタスクは `days: everyday` にすることを勧めます。

寝るタスクのない種類の日は、おやすみモードの時間が「起床時刻より前」だけになります。
たとえば寝るタスクを平日だけにすると、土曜の夜は寝る時刻になってもおやすみモードに入らず、夜 0 時になると「ｵﾔｽﾐ」を見せて首を下げ、急に静かになります。
平日と休日で寝る時刻を変えたいときは、`days: weekday` と `days: holiday` の寝るタスクを 1 つずつ書きます（同じ種類の日に寝るタスクを 2 つは書けません）。

### 設定が誤っているとき

設定に誤りがあると、日課は開始せず、ロボットの画面に設定の誤りが出ます。
誤りの場所（例: `tasks.0.at` は 1 つ目のタスクの `at`）と理由が、ログに出ます（設定の値は出しません）。
`python -m osekkai --self-check` でも、`core.config` の項目で分かります。

## 3. サンプルからの写し方

前の日課のサンプル（`routine.example.yaml` の形の設定）を使っていたときは、次のように写します。
写すのは、保護者が手元の設定ファイルの間で行います。リポジトリや手順書に、写した値を書かないでください。

| サンプルのキー | 新しいキー |
| --- | --- |
| `child.call_name` | `routine.call_name` |
| `calendar.extra_holidays` | `routine.extra_holidays` |
| `tasks` | `routine.tasks`（タスクの中のキーは同じ名前のまま） |

- タスクの中のキー（`id`・`at`・`after`・`days`・`call`・`praise`・`lcd`・`notice`・`notice_min`・`ready`・`remind_min`・`max_reminders`・`firm`・`sleep`）は、そのまま写せます
- サンプルで `days` を書いていなかったタスクは、毎日のタスクです（新しい設定でも同じ）
- 時刻は引用符で囲み直します（`"07:00"`）
- タスクの中に知らない項目があると誤りになります。書き間違いがないか見ます
- サンプルの記録（星の数）は引き継ぎません。星は 0 から始まります

## 4. 起動の声の時間帯を直す

基盤は、決まった時間帯（`core.startup_voice_hours`、既定は `["08:00", "20:00"]`）に起動すると、声で知らせます。
この声は、おやすみモードかどうかを見ません。おやすみモードの時間と重なると、夜や朝早くに再起動したときに声が出ます。

self-check で次のように出たら、重なっています。

```
よい routine.quiet_hours 起動の声の時間がおやすみの時間と重なる
```

直し方: `core.startup_voice_hours` を、起床時刻の最も遅い時刻より後に始まり、寝るタスクの最も早い時刻より前に終わるようにします。
たとえば、起床が `"07:30"`、寝るのが `"19:30"` なら、次のようにします（時刻は例です）。

```yaml
core:
  startup_voice_hours: ["08:00", "19:00"]
```

## 5. self-check の項目

`python -m osekkai --self-check`（実機では `rover-deploy self-check`）に、日課の項目が 3 つ出ます。

| 項目 | 確かめること |
| --- | --- |
| `routine.holidays` | 祝日を判定できるか |
| `routine.quiet_hours` | 起動の声の時間帯が、おやすみモードの時間と重ならないか |
| `routine.records` | 記録を読めるか、壊れた記録が残っていないか、記録の置き場所に書けるか |

### 「よい」に理由が付いているとき（知らせ）

版を戻しても直らないことは、「よい」に理由を添えて知らせます。日課は動きます。保護者が直すと消えます。

| 理由 | すること |
| --- | --- |
| 起動の声の時間がおやすみの時間と重なる | [4. 起動の声の時間帯を直す](#4-起動の声の時間帯を直す) |
| 記録を読めない | 日課が次に起動したときに、壊れた記録を別の名前で残して、星の数の控えから続けます。その後に残ったファイルを消します（下） |
| 壊れた記録が残っている | 残ったファイルを消します（下） |

### 「だめ」のとき

日課が動けないときだけ「だめ」になります。配置の道具は、だめの項目があると前の版に戻します。

| 理由 | 考えられること |
| --- | --- |
| 祝日を判定できない | 祝日の部品（jpholiday）が入っていない。版の入れ直しで直ります |
| 記録を書けない | 記録の置き場所（下）に書く権限がない、ディスクがいっぱい |

`routine.quiet_hours` が「飛ばした（日課の設定を使えない）」のときは、日課の設定に誤りがあります。`core.config` の項目を見ます。

### 残った記録の消し方

日課の記録は `~/.local/state/osekkai/routine/`（`$XDG_STATE_HOME/osekkai/routine/`）にあります。
壊れた記録と、版の違う記録は、消さずに別の名前で残します。

| ファイル | 中身 |
| --- | --- |
| `records.json` | 今の記録。消さない |
| `stars.json` | 星の数の控え。消さない |
| `*.corrupt-*.json` | 読めなかった記録 |
| `records.other-version-*.json` | 版の違う記録 |

中身を見て要らなければ、ロボットの上で次のように消します。

```sh
ls ~/.local/state/osekkai/routine/
rm ~/.local/state/osekkai/routine/*.corrupt-*.json
rm ~/.local/state/osekkai/routine/records.other-version-*.json
```

消した後に self-check を行うと、知らせが消えます。

## 6. 試しに 1 つ動かす

設定のタスクを 1 つだけ、時刻を待たずに動かせます。記録と星の数は変わりません。

```sh
python -m osekkai.features.routine --try <タスクの id> [--fast] [--fake-hardware] [--config PATH]
```

| 引数 | 意味 |
| --- | --- |
| `--try <id>` | 動かすタスクの `id` |
| `--fast` | 催促の間隔を 10 秒、あとでの受付を 30 秒にして、早く進める |
| `--fake-hardware` | ハードなしで、端末に画面と声を出す（PC で確かめる） |
| `--config PATH` | 別の設定ファイルを使う |

- 進み方は本番と同じです（準備・声かけ・催促・あとで・ほめる）
- 終わると、結果の種類（できた・スキップ・中断）を 1 行出して終わります
- 寝るタスクを試すと、おやすみの表示を 3 秒見せて終わります。おやすみモードには入りません
- ロボットのサービスが動いているときは「ロボットが動いています。止めてから試してください」と出て、終了コード 75 で終わります。止めてから試します
- ない `id` を指定すると、設定のタスクの `id` の一覧を出して、終了コード 2 で終わります。日課の設定に誤りがあると、終了コード 1 で終わります
- 日課が無効（`routine.enabled: false`）のときと、`--fake-hardware` なしで実機のアダプタを読み込めないとき（PC など）も、理由を出して終了コード 1 で終わります
- 途中で Ctrl+C を押すと、ロボットを止めて「中断」を 1 行出し、終了コード 0 で終わります
- 基盤の起動の声（`core.startup_voice_hours` の間）は、試しでも流れます
