# だるまさんの手順書

だるまさんは、ロボットが鬼になって子どもと「だるまさんがころんだ」をする機能です（機能の名前は `daruma`）。
ロボットは首をそらして唱え、「ころんだ！」で振り向いて、首のカメラで動いたかを見ます。ロボットは走りません。
機能は `src/osekkai/features/daruma/` にあります。

この手順書は、保護者が設定を変えるとき、動いたかの判定を部屋に合わせるとき、実機で確かめるときに見るものです。

## 1. 遊び方

1. ボタンを押して「だるまさん しよう」と話しかけると始まります。「だるま」か「転んだ」を含む言葉なら始まります（[`docs/voice.md`](voice.md)）
2. ロボットが「だるまさんが ころんだ、しよう！ローバーが おにだよ。ローバーから はなれて、スタートの ところに いってね」と話します。子どもはロボットから離れて、スタートの場所に行きます
3. 5 秒たつと「10かいの うちに ローバーに タッチ できたら {呼び名}の かち。いくよー！」と話して、1 回目を始めます。「10」は設定の回数（`max_rounds`）です。ここまでに押したボタンは数えません
4. 1 回の流れ
   - 最後の 3 回は、唱える前に「あと さんかい」「あと にかい」「さいごの いっかい」と話します（回数が 3 より少ないときは、1 回目の残りから）
   - ロボットは首を横にそらして、「だーるーまーさーんーがー」「だるまさんが」「だるまさんがー」のどれかを唱えます（毎回ランダム）。唱えた後、0〜1.2 秒の間を置きます
   - 首を正面に向け、LCD に「ﾐﾃﾙﾖ!」を出して「ころんだ！」と話し、2.5 秒（既定）の間、カメラで動きを見ます

決まり:

| とき | どうなるか |
| --- | --- |
| 唱えている間（その後の間を含む）にボタンを押した | 子どもの勝ち。LCD に「♥ ﾀｯﾁ! ｶﾁ! ♥」を出し、首だけで踊りながら「タッチ されちゃった！{呼び名}の かち！やったね！」と話して終わります |
| 見ている間に動いた | 「動いた」。LCD に「ｳｺﾞｲﾀ!」を出し、うなずいて「あっ、うごいた！スタートに もどってね」と話します。5 秒待ってから次の回です。この 5 秒の間の押下は数えません |
| 見ている間にボタンを押した | 動いたことにします（見ている間はタッチしても勝ちになりません） |
| 動かなかった | すぐに次の回です |

- ロボットの本体のボタンと、足したボタン（基盤の設定の `extra_button_pin`）は、同じに扱います
- 呼び名（`call_name`）が空なら「きみ」と呼びます
- 勝っても星は増えません。遊びの記録も残しません
- 遊びの間、タイヤは回しません（踊るときも）。首は基盤の設定の範囲の中でだけ動かします
- 遊びの間に押したボタンは遊びにだけ使います。話しかけの聞き取りは始まりません。見つけてあいさつは顔を探さず、あいさつもしません

終わり方:

| とき | 話す言葉 |
| --- | --- |
| 勝った | タッチ されちゃった！{呼び名}の かち！やったね！ |
| 10 回（`max_rounds`）のうちにタッチできなかった（ローバーの勝ち） | おしまい！こんどは ローバーの かち。また あそぼうね |
| 日課の次のタスクまで 10 分（`end_before_task_min`）を切った・タスクの最中になった | あ、つぎの よていの じかんが ちかいね。また あそぼうね |
| 遊びの途中でカメラが使えなくなった | ごめんね、カメラが うまく うごかないみたい。また あそぼうね |

始めないとき:

| とき | 話す言葉 |
| --- | --- |
| カメラを使えない（カメラがない・見つけてあいさつが動いていない・カメラを借りられない） | ごめんね、カメラが ないと あそべないんだ |
| 日課の次のタスクが近い・タスクの最中 | あ、つぎの よていの じかんが ちかいね。また あとで あそぼうね |
| 声・画面・ボタン・首をほかの機能が使っている | 何も話しません |
| もう遊んでいる | 何も話しません（遊びは 1 つだけ） |

- 日課のタスクの時刻になって、日課が声や首を使うときは、いま話している一言を言い終えてから譲り、何も話さずに終わります
- おやすみモードになったら、何も話さずに終わります
- どの終わり方でも、首を正面に戻し、カメラを見つけてあいさつに返します。その後は、話しかけと見つけてあいさつがいつもどおり動きます
- 日課が動いていないときは、次の予定はないものとして遊びます

## 2. 設定の書き方

設定は、基盤と同じ設定ファイル `~/.config/osekkai/config.yaml` の `daruma:` の節に書きます。
見本（[`config/osekkai.example.yaml`](../config/osekkai.example.yaml)）の `daruma:` の節は既定値です。そのままで動きます。
設定を変えたら、ロボットを起動し直します。設定は起動のときに読みます。

```yaml
daruma:
  enabled: true
  call_name: ""
  threshold: 0.01
  watch_seconds: 2.5
  max_rounds: 10
  end_before_task_min: 10
```

| 項目 | 既定値 | 意味 |
| --- | --- | --- |
| `enabled` | `true` | `false` にすると、だるまさんは開始せず、始める言葉も登録しません |
| `call_name` | `""` | 子どもの呼び名。始めと勝ちの言葉で使います。空なら「きみ」 |
| `threshold` | `0.01` | 動いたとするしきい値。動きの量（映像のうち変わった部分の割合、0〜1）がこれより大きいと「動いた」。0 より大きく 1 より小さい値。大きいほど甘くなります（3 章） |
| `watch_seconds` | `2.5` | 「ころんだ！」の後に動きを見る長さ（秒、1〜10） |
| `max_rounds` | `10` | この回数のうちにタッチできたら子どもの勝ち。できなければローバーの勝ちで終わります（1〜50）。止まり続けていても、この回数までは遊びます |
| `end_before_task_min` | `10` | 日課の次のタスクの何分前から遊ばないか（分、0〜120）。0 ならタスクの時刻まで遊べます |

- だるまさんは見つけてあいさつのカメラを使います。見つけてあいさつが無効（`presence.enabled: false`）なら遊べません
- 呼び名は個人の情報です。見本の値は空のままにし、実機の設定ファイルにだけ書きます
- 設定に誤り（範囲の外など）があると、だるまさんは開始しません。ほかの機能は動きます。誤りの場所（キーのパス）と理由はログに、誤りの件数は self-check の `core.config` に出ます。値は出しません
- 話しかけで始めるので、音声の入口が言葉を渡さない時間帯の外とおやすみモードの間は、始まりません

## 3. しきい値の合わせ方

部屋の明るさやカメラの位置で、止まっていても動きの量が少し出ることがあります。
止まっているのに「うごいた」になるときはしきい値を大きく、動いても「とまってる」になるときは小さくします。

1. 4 章のとおりロボットのサービスを止めて、判定を確かめる道具を動かします

   ```sh
   .venv/bin/python -m osekkai.features.daruma --judge-test --seconds 60
   ```

2. ロボットの前（遊ぶときのスタートの場所あたり）で、止まっている時と、少し動いた時を試します。設定の見る長さ（`watch_seconds`）ごとに、次のような行が出ます

   ```text
     2.5 秒  動きの量 0.000  とまってる
     5.0 秒  動きの量 0.004  とまってる
     7.5 秒  動きの量 0.030  うごいた
   ```

3. 止まっている時の量より大きく、動いた時の量より小さい値を `threshold` に書きます。ロボットを起動し直して、もう一度確かめます

- 道具は、遊びと同じ見る長さ・同じ判定で確かめます。首は正面（遊びで見るときの向き）に向けます
- 見つけてあいさつの `--motion-test`（[`docs/presence.md`](presence.md) の 5 章）でも動きの量を見られます。こちらは 2 秒ごとの量なので、遊びの見る長さとは違います。しきい値を決めるときは `--judge-test` を使います

## 4. 道具

話しかけずに遊びを 1 回始める道具と、判定を確かめる道具があります。
どちらも、ロボットのサービスを止めてから、実機で動かします。子どもが使っていない時間に行います。
動いたままだと「ロボットが動いています。止めてから実行してください」と出て、終了コード 75 で終わります（何もしません）。

```sh
systemctl --user stop osekkai.service          # 1. サービスを止める
cd ~/osekkai-rover/current
.venv/bin/python -m osekkai.features.daruma --play     # 2. 道具を動かす（例は遊びを 1 回）
systemctl --user start osekkai.service         # 3. 終わったらサービスを起動する
```

使い方:

```text
python -m osekkai.features.daruma (--play | --judge-test) [--seconds N] [--fake-hardware] [--config PATH]
```

| 指定 | 意味 |
| --- | --- |
| `--play` | 話しかけたときと同じ遊びを 1 回して終えます。終わったら `終わり方: win` のように終わり方の名前を 1 行出します |
| `--judge-test` | 見る長さごとの動きの量と、設定のしきい値での「うごいた」「とまってる」を出し続けます（3 章） |
| `--seconds N` | `--judge-test` で確かめる秒数（1〜600 の整数。既定は 30）。`--play` とは使えません |
| `--fake-hardware` | 実機の代わりに端末で動かします（偽のカメラ。Enter キーがボタン。5 章） |
| `--config PATH` | 設定ファイルを指定します |

- `--play` と `--judge-test` は、どちらか 1 つを付けます
- 道具の中で見つけてあいさつも動き、そのカメラを借ります。見つけてあいさつが動き出すのを最長 10 秒待ちます
- 道具の中では日課と音声の入口は動きません。次の予定は見ず、ボタンの押下は遊びにだけ使います
- 途中で Ctrl+C で止めても大丈夫です。首を正面に戻し、カメラを返して終わります

`--play` が出す終わり方の名前:

| 名前 | 意味 |
| --- | --- |
| `win` | 子どもの勝ち |
| `max_rounds` | 回数を終えた（ローバーの勝ち） |
| `next_task` | 日課の次のタスクが近い |
| `no_camera` | カメラを使えないので始めなかった |
| `camera_lost` | 途中でカメラが使えなくなった |
| `busy` | 声・画面・ボタン・首を借りられなかった |
| `preempted` | 優先度の高い機能に譲った |
| `quiet` | おやすみモードになった |
| `stopped` | 途中で止めた（Ctrl+C など） |
| `error` | そのほかの失敗 |

`--judge-test` は、終わると次のどれかを出します。

| 出る文 | 意味 |
| --- | --- |
| 確かめ終えました | 決めた秒数を確かめ終えた |
| 途中で止めました | Ctrl+C などで止めた |
| カメラが使えなかったので、確かめるのをやめました | カメラを借りられなかった・途中で使えなくなった |
| 確かめるのに失敗しました | そのほかの失敗 |

終了コード:

| コード | 意味 |
| --- | --- |
| 0 | できた（`--play` の `win`・`max_rounds`・`next_task`・`preempted`・`quiet`・`stopped`、`--judge-test` の「確かめ終えました」「途中で止めました」） |
| 1 | できなかった（`--play` の `no_camera`・`camera_lost`・`busy`・`error`、`--judge-test` の「カメラが使えなかったので、確かめるのをやめました」「確かめるのに失敗しました」、「道具の機能を始められませんでした」、設定の誤り、だるまさんが無効、`--fake-hardware` なしで実機のアダプタを読み込めない） |
| 2 | 指定の誤り（`--play` と `--judge-test` のどちらもない・両方ある、`--seconds` の範囲の外、`--seconds` を `--play` と使った） |
| 75 | ロボットが動いている（止めてから実行します） |

- 設定に誤りがあると「設定の誤り: 」に続けて場所と理由を出します（値は出しません）
- だるまさんが無効のときは「だるまさんが無効になっています（daruma.enabled）」と出ます

## 5. PC で試す（ハードなし）

開発 PC には首のカメラがありません。`python -m osekkai --fake-hardware` で「だるまさん しよう」と打つと、「ごめんね、カメラが ないと あそべないんだ」と答えて始まりません。
遊びの流れは、道具に `--fake-hardware` を付けて見ます。

```sh
python -m osekkai.features.daruma --play --fake-hardware
```

- 端末に、LCD の文字・首の角度・話す言葉が出ます
- 端末で Enter キーを押すと、ボタンを押したことになります。唱えている間に押すと勝ちです
- 偽のカメラは、決まった動きの量（0.000、0.004、0.030）を順に返します。しきい値が既定の 0.01 なら、「とまってる」「とまってる」「うごいた」の順になります
- 判定の道具も同じように試せます

  ```sh
  python -m osekkai.features.daruma --judge-test --seconds 8 --fake-hardware
  ```

## 6. データの扱い

- カメラの映像・静止画・動きの量は、ファイルにもログにも残しません。動きの量は、判定の道具が画面（端末）に出すだけです
- 遊びの記録・勝ち負け・回数は残しません。星も増やしません
- 呼び名は、ログ・self-check の結果に出しません。ログには決まった文言・終わり方の種類・回数・誤りの種類の名前だけを出します
- 映像と動きの量は、外部に送りません

## 7. self-check の項目

`python -m osekkai --self-check`（実機では `rover-deploy self-check`）に、`daruma.camera` が出ます。いま遊べるか（カメラを使えるか）を確かめます。
遊べなくても「だめ」にはしません（カメラのハードは `presence.camera` が確かめます。設定の問題は版を戻しても直らないため）。「よい」に理由を添えて知らせます。

| 結果 | 理由 | 直し方 |
| --- | --- | --- |
| よい | （なし） | 遊べます |
| よい | 見つけてあいさつの設定を使えないので遊べない | `presence:` の節を直します。`core.config` を見ます |
| よい | 見つけてあいさつが無効なので遊べない | 遊ぶときは `presence.enabled: true` にします |
| よい | 見つけてあいさつが動いていないので遊べない | 見つけてあいさつの項目（`presence.camera` など）を見ます（[`docs/presence.md`](presence.md) の 7 章） |
| 飛ばした | 無効 | 設定で `enabled: false` のときです |
| 飛ばした | 設定を使えない | 設定ファイルがないか、誤りがあるときです。`core.config` を見ます |
| 飛ばした | ロボットが動いていないので確かめない | ロボットが止まっているときです。カメラのハードは `presence.camera` を見ます |

## 8. 実機で確かめる

子どもが使っていない時間に、保護者が実機で次を確かめます。

1. self-check で `daruma.camera` が理由なしの「よい」になる
2. 4 章のとおりサービスを止めて `--judge-test` を動かし、止まっていると「とまってる」、動くと「うごいた」になる。合わなければ 3 章のとおりしきい値を直す
3. サービスを起動して、ボタンを押して「だるまさん しよう」と話すと、始めの言葉の後に唱え始める
4. 唱えている間にボタンを押すと、勝ちの言葉を話して首で踊る。タイヤは回らない
5. 「ころんだ！」の後に動くと「あっ、うごいた！スタートに もどってね」と話す。見ている間にボタンを押しても同じになる
6. 止まったまま押さずにいても、途中で終わらない。最後の 3 回は唱える前に残りの回数を話し、10 回で「おしまい！こんどは ローバーの かち。また あそぼうね」と話して終わる
7. 遊んでいる間にボタンを押しても、話しかけの聞き取りが始まらない
8. 遊びが終わった後、ボタンを押して話しかけると、いつもどおり聞き取る。見つけてあいさつも顔を追う
9. ログ（`journalctl --user-unit=osekkai.service -b`）に、呼び名と動きの量が出ていない
