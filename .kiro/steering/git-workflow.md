# Git ワークフロー

[目的: main を「いつでも実機（Raspberry Pi 5）に入れられる状態」に保ち、実機に入る版をタグで明確にする]

## 方針
- **main と短命な作業ブランチだけ**を使う（GitHub Flow）。develop / release ブランチは作らない
  - 理由: 実機が 1 台で、develop を動かす別の環境がない。分けても検証の段階は増えず、二重マージとずれが増えるだけ
  - 見直す条件: 検証用の 2 台目を用意したとき、または複数人で並行開発してまとめてリリースしたくなったとき（まず `vX.Y.Z-rc1` の候補タグで足りるか検討する）
- **実機に入れるのはタグを付けた版だけ**。main は「CI と必要な実機確認を通ったもの」、タグは「普段使いに入れたもの」

## ブランチ
| 種類 | 名前 | 用途 |
| --- | --- | --- |
| 機能 | `feat/<feature>` | スペックに基づく開発。`<feature>` は `.kiro/specs/<feature>` と同じ名前 |
| 修正 | `fix/<内容>` | 不具合の修正 |
| 文書 | `docs/<内容>` | README・ステアリングなど |
| 雑務 | `chore/<内容>` | CI・設定・依存関係 |

- 名前は英小文字とハイフン（例: `feat/safe-shutdown`, `fix/lcd-garbled`）
- main から切り、マージしたら削除する。長く残さない（目安: 数日）
- main への直接 push は禁止（GitHub のルールセットで強制）

## コミット
- [Conventional Commits](https://www.conventionalcommits.org/ja/) の型 + 日本語の説明
  ```
  feat: 走行中はデプロイを中止する
  fix: SIGTERM でモーターが止まらない問題を直す
  docs: README にラジコンの使い方を追加
  ```
- 型: `feat` / `fix` / `docs` / `chore` / `refactor` / `test`
- 1 コミット 1 目的。生成物・個人データを混ぜない

## プルリクエスト
- 1 PR 1 目的。スペックの作業なら PR 本文にスペック名とタスク番号を書く
- `.github/pull_request_template.md` のチェック項目を埋める
- マージ条件:
  - CI（`guard` ほか）が成功している
  - ハード（モーター・サーボ・カメラ・LCD・音声・ボタン）に関わる変更は、実機確認の結果が書かれている
- マージは **squash** のみ。main の履歴は「1 PR = 1 コミット」
- 1 人開発のため承認数は 0。代わりに Kiro のレビュー（`/kiro-impl` のレビュー、`/kiro-validate-impl`）を通す

## Kiro との対応
```
スペック承認 → feat/<feature> を切る → /kiro-impl → /kiro-validate-impl
  → 実機確認（ハードに関わる場合）→ PR → squash マージ → 必要ならタグ
```

## 実機確認
- 実機は子どもが毎日使っている 1 台なので、試すのは**使っていない時間帯**（声かけの予定がない時間）にする
- 作業ブランチを実機で試したら、**終わったら必ず最新のタグに戻す**
- 走行中には入れ替えない。停止時は必ずモーターを止める
- 具体的な手順（デプロイスクリプト・自己診断）はデプロイのスペックで整備する

## リリース
- タグは `vX.Y.Z`（[セマンティック バージョニング](https://semver.org/lang/ja/)）。main のコミットにだけ付ける
  - X: 設定ファイル（`config/local.yaml`）や記録の形式が変わり、手作業が要る
  - Y: 機能の追加
  - Z: 不具合の修正
- タグには注釈を付け、変更点を短く書く（`git tag -a v0.1.0 -m "..."`）

## 公開リポジトリとして守ること
このリポジトリは公開されている。次のものは**絶対にコミットしない**（`.gitignore` と CI の `guard` で防ぐ）。
- 子どもの名前・時刻などの個人設定（`config/local.yaml`）と記録（`data/`）
- 顔の特徴（`*.npz`）、音声・写真・動画
- API キー・ラジコンの pin などの秘密情報
- 実機の IP アドレスやホスト名（接続先は開発 PC の `~/.ssh/config` に置く）
- zip などのアーカイブ

誤ってコミットした場合は、push 前ならコミットを作り直す。push 後なら秘密情報を無効化（API キーの再発行など）してから履歴を消す。
