# Requirements Document

## Project Description (Input)
子どもは、ロボットと体を動かして遊びたい。保護者は、ロボットが走り回らず、安全に遊べることを求めている。

今は、サンプルの `games.py` に「だるまさんがころんだ」がある。「だるまさん しよう」と話しかけると始まり、ロボットが鬼になって首をそらして唱え（速さは 3 種類からランダム）、「ころんだ！」で振り向いてカメラで動きを見る（既定 2.5 秒）。動いたら「スタートに もどってね」と言い、ロボットのボタンを押せたら子どもの勝ちでダンスする。最大 15 回か、次の予定が近いと終わる。ロボットは走らない。ただし、見ている間にボタンが押されると動いたことより押したことが優先される、ほかの機能の資源（首やカメラ）を直接触っている、という問題がある。

`rover-core` の機能として daruma-game を作る。`voice-gateway` に始める言葉を登録し、`presence` が出す動きの量を使う。子どもから見た遊び方はサンプルと同じにし、「動いた」と「押した」が同時のときの扱いをルールとして決め、日課のタスクが始まるときは遊びをやさしく終える。遊びの流れ（回、勝ち負け、終わり方）は偽の動きとボタンで PC でテストできるようにする。詳しくは `.kiro/specs/daruma-game/brief.md` を参照。

## Introduction
だるまさんがころんだ（daruma-game）は、ロボットが鬼になって子どもと遊ぶ機能です。子どもが話しかけて始め、ロボットは首をそらして「だるまさんが…」と唱え、「ころんだ！」で振り向いてカメラで動きを見ます。動いた子はスタートに戻り、唱えている間にロボットのボタンを押せたら子どもの勝ちです。ロボットは走りません。

遊びの流れ（回、勝ち負け、終わり方）は、サンプルの振る舞いを踏襲します。サンプルで決まっていなかったことは、次のとおりに決めます。見ている間に押したときは「動いた」とする。日課の次のタスクが近いときは早めに終える。決めた回数のうちにタッチできなければ、ローバーの勝ちで終える。

初めは「続けて止まっていたら、だれもいないとして終える」決まりがあった。しかし、止まるのが上手な子と、だれもいないのは見分けられず、上手な子が遊びを終えられてしまった。そこでこの決まりをやめ、回数の決まり（ローバーの勝ち）と残りの回数の知らせにした。

用語:
- **唱える間**: 首をそらして唱え言葉を話し始めてから、「ころんだ！」を話し始めるまで
- **見ている間**: 「ころんだ！」を話し始めてから、動きを見終わるまで
- **動きの量**: カメラの映像のうち、変わった部分の割合（0〜1）。`presence` が出す
- **1 回**: 唱える間と見ている間の 1 組

## Boundary Context
- **In scope**: 始める言葉の登録と始め方、1 回の流れ（唱える・振り向く・見る・判定）、勝ち負けとその言葉と動き、終わり方（回数とローバーの勝ち・残りの回数の知らせ・次の予定・おやすみ・譲る）、動いたかどうかのしきい値などの設定、遊びの間の資源とカメラの扱い、手で遊びを始めて確かめる道具、しきい値で判定した結果を確かめる道具、self-check の項目、開発 PC で偽の動きとボタンを使って確かめられること
- **Out of scope**: 動きの量の計算とカメラの操作（`presence`）、動きの量そのものを確かめる道具（`presence` の `--motion-test`）、ボタンを押してからの聞き取りと言葉の振り分け（`voice-gateway`）、日課のタスクの判定（`daily-routine`）、走ること、星を増やすこと、遊びの記録を残すこと
- **Adjacent expectations**:
  - `voice-gateway` は、登録した言葉が含まれる聞き取りを、この機能に渡す。聞ける時間帯の外とおやすみの間は言葉を渡さない
  - `presence` は、カメラを貸し出して動きの量を出す。貸している間、顔を探さず、首を動かさず、あいさつしない
  - `daily-routine` は、今日のこの後の最も早いタスクの時刻と、タスクの最中かどうかを知らせる。タスクを始めるときは、優先度の低い機能から資源を取り上げる
  - `rover-core` は、声・LCD・ボタン・首の資源の調停、静かな状態（おやすみ）、self-check の口を提供する

## Requirements

### Requirement 1: 遊びを始める
**Objective:** As a 子ども, I want 「だるまさん しよう」と話しかけると遊びが始まること, so that ロボットとすぐ遊べる

#### Acceptance Criteria
1. When `voice-gateway` から「だるま」か「転んだ」を含む言葉を受け取ったとき, the Daruma Game shall 遊びを始める
2. When 遊びを始めるとき, the Daruma Game shall LCD に「ﾀﾞﾙﾏｻﾝｶﾞ」「ｺﾛﾝﾀﾞ!」を出し、「だるまさんが ころんだ、しよう！ローバーが おにだよ。ローバーから はなれて、スタートの ところに いってね」と話す
3. When 始めの言葉を話し終えてから 5 秒たったとき, the Daruma Game shall 「{回数}かいの うちに ローバーに タッチ できたら {呼び名}の かち。いくよー！」と話し（{回数} は設定の回数を数字で書く）、それまでに押されたボタンを数えずに 1 回目を始める
4. If カメラを使えないとき（カメラがない、見つけてあいさつが動いていない、カメラを借りられない）, the Daruma Game shall 「ごめんね、カメラが ないと あそべないんだ」と話して、遊びを始めない
5. If 日課の次のタスクの時刻まで、決めた長さ（既定は 10 分）を切っているとき、または日課のタスクの最中のとき, the Daruma Game shall 「あ、つぎの よていの じかんが ちかいね。また あとで あそぼうね」と話して、遊びを始めない
6. If 声・LCD・ボタン・首を借りられないとき, the Daruma Game shall 何も話さずに、遊びを始めない

### Requirement 2: 1 回の流れ
**Objective:** As a 子ども, I want ロボットが本物の鬼のように唱えて振り向くこと, so that だるまさんがころんだを楽しめる

#### Acceptance Criteria
1. When 1 回を始めるとき, the Daruma Game shall 唱え言葉を「だーるーまーさーんーがー」「だるまさんが」「だるまさんがー」の 3 つから毎回ランダムに選び、LCD にその言葉（「ﾀﾞｰﾙｰﾏｰｻｰﾝｶﾞｰ」「ﾀﾞﾙﾏｻﾝｶﾞ」「ﾀﾞﾙﾏｻﾝｶﾞｰ」）を出す
2. When 唱え始めるとき, the Daruma Game shall 首を横にそらしてから、唱え言葉を話す
3. When 唱え言葉を話し終えたとき, the Daruma Game shall 0〜1.2 秒のランダムな間を置く
4. When その間が終わったとき, the Daruma Game shall 首を正面に向け、LCD に「ﾐﾃﾙﾖ!」と呼びかけの顔を出し、「ころんだ！」と話す
5. When 「ころんだ！」を話し終えたとき, the Daruma Game shall 決めた長さ（既定は 2.5 秒）の間、動きの量を見る
6. When 見終わった後に、動きの量が決めたしきい値（既定は 0.01）より大きいとき、または見ている間にボタンが押されていたとき, the Daruma Game shall 「動いた」と判定する
7. When 「動いた」と判定したとき, the Daruma Game shall LCD に「ｳｺﾞｲﾀ!」と呼びかけの顔を出し、1 回うなずき、「あっ、うごいた！スタートに もどってね」と話す
8. When 「あっ、うごいた！…」を話し終えたとき, the Daruma Game shall 5 秒待ってから次の回を始め、その 5 秒の間に押されたボタンを数えない（スタートに戻る途中の押下を勝ちにしない）
9. When 「動いた」と判定しなかったとき, the Daruma Game shall 間を置かずに次の回を始める

### Requirement 3: 子どもの勝ち
**Objective:** As a 子ども, I want 鬼が唱えている間にタッチできたら勝ちになること, so that 近づいてタッチする楽しさがある

#### Acceptance Criteria
1. When 唱える間（唱え言葉を話している間と、その後のランダムな間）にボタンが押されたとき, the Daruma Game shall 子どもの勝ちとする
2. The Daruma Game shall ロボットの本体のボタンと、設定で決めた追加のボタンの、どちらの押下も同じに扱う
3. When 子どもの勝ちのとき, the Daruma Game shall LCD に「♥ ﾀｯﾁ! ｶﾁ! ♥」と喜んだ顔を出し、首だけで踊りながら、「タッチ されちゃった！{呼び名}の かち！やったね！」と話して、遊びを終える
4. The Daruma Game shall 呼び名を設定から読み、設定がなければ「きみ」とする
5. The Daruma Game shall 勝っても星を増やさない

### Requirement 4: 遊びの終わり方
**Objective:** As a 保護者, I want 遊びが長く続きすぎず、決めた回数や日課の前で自然に終わること, so that 生活の流れを乱さない

#### Acceptance Criteria
1. When 決めた回数（既定は 10 回）を終えてもタッチされなかったとき, the Daruma Game shall ローバーの勝ちとし、「おしまい！こんどは ローバーの かち。また あそぼうね」と話して、遊びを終える。止まり続けていても、回数を終えるまでは終えない
2. When 残りの回数（その回を含む）が 3・2・1 の回を始めるとき, the Daruma Game shall 唱え言葉の前に、それぞれ「あと さんかい」「あと にかい」「さいごの いっかい」と話す。決めた回数が 3 より少ないときは、1 回目の残りの回数から話す
3. When 次の回を始める前に、日課の次のタスクの時刻まで決めた長さ（既定は 10 分）を切ったとき、または日課のタスクの最中になったとき, the Daruma Game shall 「あ、つぎの よていの じかんが ちかいね。また あそぼうね」と話して、遊びを終える
4. If 遊びの途中で、より優先度の高い機能（日課など）が資源を求めたとき, the Daruma Game shall いま話している一言を言い終えてから資源を返し、それ以上は何も話さずに遊びを終える
5. If 遊びの途中で静かな状態（おやすみ）になったとき, the Daruma Game shall 何も話さずに遊びを終える
6. If 遊びの途中でカメラが使えなくなったとき, the Daruma Game shall 「ごめんね、カメラが うまく うごかないみたい。また あそぼうね」と話して、遊びを終える
7. When 遊びを終えるとき（どの終わり方でも）, the Daruma Game shall 首を正面に戻し、カメラと資源を返して、見つけてあいさつや音声の入口がいつもどおり動ける状態に戻す
8. If 日課が動いていないとき, the Daruma Game shall 次の予定はないものとして遊ぶ
9. While 遊んでいる間, the Daruma Game shall 2 つ目の遊びを始めず、遊びを始める言葉が届いても答えない

### Requirement 5: 安全
**Objective:** As a 保護者, I want 遊びの間にロボットが走らないこと, so that 子どもがぶつかったり、ロボットが落ちたりしない

#### Acceptance Criteria
1. The Daruma Game shall 遊びの間（踊るときを含む）、タイヤを回さない。ダンスでタイヤを回してよいという基盤の設定があっても回さない
2. The Daruma Game shall 首を、基盤の設定で決めた範囲の中でだけ動かす
3. If 遊びの途中で誤りが起きたとき, the Daruma Game shall その遊びだけを終え、首を正面に戻し、ロボットのほかの機能を動かし続ける

### Requirement 6: 遊びの間のほかの機能との関係
**Objective:** As a 子ども, I want 遊んでいる間に押したボタンが遊びにだけ使われること, so that タッチしたのに話しかけの聞き取りが始まったりしない

#### Acceptance Criteria
1. While 遊んでいる間, the Daruma Game shall ボタンの押下を遊びだけに使い、音声の入口の聞き取りを始めさせない
2. While 遊んでいる間, the Daruma Game shall 見つけてあいさつに、顔を探したり首を動かしたりあいさつしたりさせない
3. The Daruma Game shall 遊びのために、カメラの映像・静止画・動きの量の記録を、ファイルにもログにも残さない

### Requirement 7: 設定と self-check
**Objective:** As a 保護者, I want 動きの判定の厳しさや遊びの長さを、家の部屋や子どもに合わせて変えられること, so that ちょうどよく遊べる

#### Acceptance Criteria
1. The Daruma Game shall 設定で、動いたとするしきい値・見る長さ・タッチする回数（最大の回数）・次の予定の何分前に終えるか・呼び名・有効かどうかを変えられるようにする
2. Where 設定で無効のとき, the Daruma Game shall 始める言葉を登録しない
3. If 設定の値が誤っているとき（範囲の外など）, the Daruma Game shall 開始せず、誤りの場所と理由をログに出し（値そのものは出さない）、ロボットのほかの機能を動かし続ける
4. The Daruma Game shall self-check で、遊べるかどうか（カメラを使えるか）を確かめた結果を出す
5. The Daruma Game shall 呼び名を、ログ・self-check の結果に出さない

### Requirement 8: 手で確かめる道具
**Objective:** As a 保護者, I want 話しかけずに遊びを始めたり、しきい値が部屋に合っているかを確かめたりできること, so that 実機で調整しやすい

#### Acceptance Criteria
1. When 保護者が遊びを始める道具を実行したとき, the Daruma Game shall 話しかけたときと同じ遊びを 1 回始め、終わったら終了する
2. When 保護者が判定を確かめる道具を実行したとき, the Daruma Game shall 決めた長さの間、見る長さごとの動きの量と、設定のしきい値で「うごいた」か「とまってる」かを、繰り返し画面に出す
3. If ロボットが動いているときに道具を実行したとき, the Daruma Game shall 始めずに、止めてから実行するよう示して終える
4. Where 開発 PC でハードなしで動かすとき, the Daruma Game shall 偽のカメラとボタンで、これらの道具を動かせる

### Requirement 9: 開発 PC で確かめられること
**Objective:** As a 開発者, I want 遊びの流れを実機なしで確かめられること, so that 子どもが使う実機に入れる前に誤りを見つけられる

#### Acceptance Criteria
1. The Daruma Game shall 偽の動きの量と偽のボタンと固定した乱数で、勝ち・動いた・最大の回数（ローバーの勝ち）・残りの回数の知らせ・次の予定・譲る・おやすみ・カメラの誤りのそれぞれの流れを、開発 PC と CI で確かめられるようにする
2. The Daruma Game shall 実機のハードやカメラがない環境でも、読み込みで失敗しない
