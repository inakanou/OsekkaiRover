## Implementation Notes
- 1.1: setuptools は空のエントリーポイントの群を宣言できない。`osekkai.features` は最初の機能を足すときに `[project.entry-points."osekkai.features"]` を書く（それまで発見の結果は空）
- 1.1: ruff 0.17 は `*.md` も整形するので、`.kiro` と `.claude` を対象から外している
- 1.1: 開発の PC は Python 3.14 の `.venv`。CI は 3.11 と 3.13 なので、3.12 以降だけの書き方を使わない
- 1.2: main のルールセットの必須のチェックに `test (3.11)` と `test (3.13)` を足すのは、リポジトリの設定（PR 本文の確認項目に書く）
- 1.3: 例外（`SpeechFailed` を含む）はすべて `core.types` にある。`Unavailable` と `Devices` は `core.ports`。pydantic の `Field` は mypy strict のため `Field(default=...)` の形で書く
- 1.3: `tests/core/` に `__init__.py` はない。テストのファイル名は tests の中で重ならないようにする
- 1.4: `FakeClock.sleep()` は時刻を進めて直ちに戻り、待っているほかのスレッドを起こさない。スレッドで回る処理（同期の見張り・待機画面・動きの待ち）は、止める合図を `threading.Event` で持つか、テストで 1 回ずつ進める口を設ける。空回りで時刻が飛ばないようにする
- 1.4: 偽物の失敗は `fail_on` に操作名を入れると `FakeDeviceError(RuntimeError)`。`SpeechFailed` などへの変換はサービスの側で行う。テストでは `fakes`（型付きの `FakeDeviceSet`）・`fake_devices`・`clock`・`xdg_dirs` の fixture を使う
- 1.5: 名前と key の検証は `core.paths.validate_name`、0700 のディレクトリ作成は `core.paths.ensure_private_dir` を使い回す。`JsonValue` は `core.storage` にある。`Paths` は作ったときに環境変数を写し取る
- 1.5: `StateStore.load` は、壊れた JSON は退避して None を返すが、EIO などの `OSError` はそのまま投げる。呼び出し側（機能の開始や静かな状態の読み込み）で受け止める
- 2.1: キャッシュを書いた直後と使ったときは、必ず `CacheManager.touch` を呼ぶ（mtime を時計の時刻にする。呼ばないと偽の時計のテストで古さの順が狂う）。`touch` はロックを取らないので、消された後の `FileNotFoundError` は呼び出し側で受け止める。上限は `CacheManager.from_paths(paths, max_mb, clock)` で MiB から作る
- 2.2: `ConfigLoader(paths, feature_models)` は「機能の名前 → 設定のモデル」の対応を受け取る（design の `feature_specs` の代わり）。`fatal_errors` があれば、機能の発見（5.2）はすべての機能を除く。誤りのある機能は `features` に入らない。見本から作るときの `OSError` は `load()` から投げられるので、Runtime（6.2）で受け止める
- 2.2: 同梱の見本は `src/osekkai/core/example_config.yaml`。`config/osekkai.example.yaml` と同じ内容であることをテストで縛っている（片方を変えたらもう片方も変える）
- 2.3: `EventBus` と `TimeSyncMonitor` のスレッドは daemon。Runtime（6.2・6.3）は起動で `bus.start()`・`monitor.start()`、停止で `bus.close()`・`monitor.stop()` を必ず呼ぶ。テストでは `bus.wait_idle(timeout)` で配達を待ち、見張りは `check_once()` で 1 回ずつ進める。受け手は、イベントの型にちょうど一致するものだけに届く
