## Implementation Notes
- 開発 PC の venv は、エントリーポイント（5.1）を足した後に `.venv/bin/pip install -e '.[dev]'` で入れ直す。faster-whisper（extras の `voice`）は開発 PC と CI には入れない。テストは faster_whisper とサブプロセスを偽物に替える
- faster_whisper を読み込めるかの判定は、`voice/adapters/whisper.py` の 1 つの補助（例: `whisper_available()`）にまとめ、機能（4.1）と self-check（4.3）はそれを呼ぶ（読み込みの向きのテストが、アダプタの外での faster_whisper を断るため）。テストではその補助を偽物に替える
- 5.1 では、`tests/test_cli_selfcheck.py` の JSON のテスト（各行が ok）を、基盤の項目は ok、入口の 2 つは skipped を受ける形にする（確かめを弱めない）
- ブランチを切り替えたら `.venv/bin/pip install -e '.[dev]'` をやり直す（エントリーポイントがブランチで違う）。読み込みの向きのテストは TYPE_CHECKING の読み込みも数えるので、numpy の型は関数の中か文字列の注釈で書く。ConfigLoader と instance_lock は __main__ だけ、core.runtime はどこからも使わない
- 言葉の判定: 漢字はかなにしないので、言葉を登録する機能は、かなと聞き取りが出しそうな漢字の形（例: 「だるまさんがころんだ」「だるまさんが転んだ」）の両方を登録する。長音の「ー」は除く（のばした言い方も一致する。子ども向けに実装のときに決めた）。alive は登録表のロックの中で呼ぶので、登録表を触らない軽い確かめにする
- 登録の口: 入口の側は `osekkai.voice.api.registry()` で登録表を取る（route・hints・take_follow_up_request）。テストは `_reset_for_tests()` を autouse の準備で呼ぶ
- 聞き取りの口: 録音の時間と文字にする時間は、流れが on_recording(True/False) の時刻と listen の戻りの時刻を Clock で測る。実機の聞き取り（3.1）は、arecord が終わったら文字にする前に on_recording(False) を呼ぶ。偽の聞き取りは tests/voice/voice_fakes.py の ScriptedRecognizer（READY でなくても listen を断らないので、流れのテストで calls が空であることを確かめる）
- 流れ: 流れは registry.hints() だけを渡すので、実機の聞き取り（3.1）が DEFAULT_HINT を前に足す。渡す直前と話す前後にも中断を確かめて捨てる。ListenOutcome は ROUTED(owner)・NOT_HEARD・NOT_UNDERSTOOD・DISCARDED・FAILED。IntentRegistry.handler_for(owner) を足した（続けて聞くに使う）
- 実機の聞き取り: whisper.py の whisper_available()・mic_present(device)・model_files_present(dir)・MODEL_FILES を、機能（4.1）と self-check（4.3）が使う（サブプロセスは whisper.py の中だけ）。開発 PC の venv に numpy はないので、テストは numpy も偽物にする（本物の numpy 2 では見直しで確かめた）。ヒントは既定のヒントの後に足し、200 文字まで
- 打った文字: 端末の偽物は take_typed_line()・typed_input_active()・_reset_typed_input_for_tests() を出す（rover-core の偽物への追加）。最後に start() した ConsoleButtons だけが行を取っておく。聞いている間にもう一度 Enter を押すと、後の行が聞き取った言葉になる（開発用なので許す）
- 入口の機能: auto で faster_whisper がなければ、いつも TypedRecognizer（端末の偽物が動いていなければ UNAVAILABLE）。within_hours は core.runtime を読めないので feature.py に写した。モデルの置き場所は Paths()（XDG）の data_dir/models/faster-whisper-<model>（`model_dir(paths, config)`）。テストは acquire_wait と job_poll を小さくする（既定は 2.0 と 1.0）。続けて聞く（4.2）の口は `_between_jobs(stop)` と `_Job.follow_up_owner`
- 続けて聞く: 押下のときにも登録表の要求を取る（求めた直後の押下を取りこぼさない）。押下と _between_jobs が同時に走ると、まれに 1 回だけ初めての聞き取りになる（受け入れた）
- self-check: model_dir は config.py に移した（feature と checks の循環を避ける）。実機で auto のまま faster-whisper が入っていないと、どちらの項目も「打った文字の聞き取り」で飛ばし、押下には「おはなし できない」と答える。5.1 の手順書に「実機の設定は recognizer: whisper にする」と書く（そうすれば、マイクとモデルがないときに self-check がだめになる）
