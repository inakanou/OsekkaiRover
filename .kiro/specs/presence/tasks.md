## Implementation Notes
- 開発 PC と CI には OpenCV・numpy・picamera2 がない。テストは cv2・numpy・picamera2 を偽の module にする。pip の依存は足さない（実機は初期設定の apt で入る）
- エントリーポイント（5.1）を足した後は `.venv/bin/pip install -e '.[dev]'` で入れ直す。ブランチを切り替えたときも入れ直す
- このブランチには日課と音声の入口のコードがない（別のブランチ）。後からマージする方で、pyproject.toml のエントリーポイント・README の機能の表・設定の見本・self-check の名前の一覧のテストを合わせる
- 1.1 は骨組みだけなので、見直しは親が差分を読んで行った。`src/osekkai/features/__init__.py` は日課のブランチにもあり、後からマージする方で合わせる
- 設定: okaeri_minutes は away_minutes 以上（小さいとやっほーが出なくなるので誤り）。覚える数 40 は texts.LEARN_SAMPLES
- 顔の帳面: 読めない faces.json（版の違い・形の誤り）は空として扱い、次の保存で上書きされる。覚えるコマンド（4.4）は、FaceBook.readable が False のときは始めず、決まった文言で「すべて消すか、バックアップから戻す」よう示して終える（ほかの人の特徴を黙って消さない）。best_match は問い合わせの特徴も正規化する（形が誤っていれば ValueError）
- 追従: 目の向きは、左右の反転の前の首の向きから決める（左右だけを反転しても目は変わらず、目の反転だけで逆になる。サンプルと同じ）。Tracker の反転はキーワードの引数
- あいさつ: decide の waiting_recognition は誰か分からないまま待った秒数（見る流れ 3.1 が渡す）。引数は now の後はキーワード。mark_seen は 60 秒に 1 回まで保存し、mark_greeted はすぐ保存する。最後に見た時刻は再起動の後も引き継ぐので、再起動の直前に見た人には再起動の直後にあいさつしない
- 偽物は tests/features/presence/presence_fakes.py（FakeFrame・FakeCamera・FakeVision・embedding(seed)）。FakeVision の特徴は 1 つのフレームに 1 つ。FakeCamera は start の前でも撮れる
- カメラ: 上下の反転は picamera のアダプタだけが libcamera の Transform で当てる（OpenCV は反転しない）。capture と capture_still は start の後でないと CameraUnavailable（偽物と違う）。libcamera は importlib で読む。実機確認で反転の向きと色の並び（BGR）を確かめる
- OpenCV: 反転しない（タスクの文には反転とあるが、カメラのアダプタだけが反転すると決めた）。VisionUnavailable は CameraUnavailable を継ぐ。embed は直前の detect の顔でないと ValueError（見る流れの 1 本のスレッドで使う）。テストは numpy を偽物にするので pytest.approx を使わない
- 見る流れ: Watcher(camera, vision, book, records, policy, tracker, config, clock, io, log)。貸し出しは start_loan/end_loan/request_motion/request_frame/request_still → LoanTicket.wait。CameraBusy・CameraNotAvailable・CameraNotBorrowed は watcher.py にあり、api（4.3）が出し直す。貸し出しの要求は run_once が行うので、機能（4.2）は首を借りていないときも貸し出し中は run_once を回す。pause は貸し出しを終えない。動きの量は見るスレッドを秒数だけ止める（api の待ちはそれより長く）。1 回見つけている間のあいさつは 1 回だけ、一度決まった人は見失うまで変えない（見直しの提案で親が直した）
- self-check: PRESENCE_CHECKS を 4.2 の申告の checks に渡す。覚えた顔の確かめは faces.py の _parse を使い、FaceBook.load と同じ決まりで判定する。カメラのライブラリがない PC と CI では、カメラとモデルの項目を飛ばす
- 機能の本体: 首とあいさつのリースは _acquire_releasing で借り、中断の知らせのスレッドからすぐに返す（見るスレッドが止まっていても 2 秒の猶予の中で返す）。カメラがなくても api の置き場に見る流れを登録する（貸し出しは CameraNotAvailable）。静かな状態の間は首も返す。テストは IdleScreen の _face・_gaze を読む
- カメラを借りる口: borrow_camera(owner, alive=...) → CameraLoan（motion・frame・still・release・with）。時間切れは TimeoutError（決まった文言）で、貸し出しは続く。motion の待ちは秒数 + 5 秒、frame と still は 10 秒
- 顔を覚える・消す・一覧（4.4）: 覚えるは presence.enabled が false だと始めない（終了コード 1）。--forget-all は横へ動かした faces.corrupt-*・greetings.corrupt-* も消す（顔のデータを残さない）。覚える前の言葉の時間も 40 秒に含む
- 確認のコマンド（4.5）: --watch-test（既定 30 秒）・--motion-test（既定 20 秒）。--seconds は 1〜3600。途中で止めても 0。動きの量は watcher の _peak_motion を使う（後で公開の名前にしてよい）。覚えると確認は _run_alone で Runtime を 1 つの機能で動かす
- 登録（5.1）: 見本の設定を読むテスト（test_config・deploy の test_calibration）は、発見した機能の設定のモデルも渡す。self-check の名前の一覧は ALL_NAMES（基盤 + presence の 3 つ）。日課・音声の入口とマージするとき、ALL_NAMES・登録のテストの ["presence"]・README の機能の表・見本の節を合わせる
- 止まるとき（最後の確認の後に直した）: 機能が止まると Watcher.close で貸し出しを終え、残った要求にすぐ CameraNotAvailable を知らせる。同じ回りの失敗が続くときは、最初の 1 回と 600 回（約 1 分）ごとのまとめだけを記録し、直ったら回数を記録する
