## Implementation Notes
- 開発 PC の venv は、依存（1.1）とエントリーポイント（3.5）を足した後に `.venv/bin/pip install -e '.[dev]'` で入れ直す。入れ直さないと jpholiday や日課の機能が見つからない
- 日課のテストの時計は `tests/features/routine/conftest.py` が根の `clock` を差し替える（Asia/Tokyo、2026-04-06（月）06:00 始まり）。補助は `routine_fixtures.py`（mypy の重複を避けるため conftest は mypy の対象外）。jpholiday 1.0.3 は型付きなので mypy の除外は要らない
- 設定の時刻: YAML の引用符なしの H:MM は 60 進の整数（60〜1439）になるので時刻に戻す。0〜59 の整数・秒つき・タイムゾーンつきは誤り。起床時刻は `RoutineConfig.wake_time(kind)`（寝るタスクは候補に入れない）を Scheduler でも使う。pydantic の `str(ValidationError)` は入力の値を含むので、ログに出さない
- 記録: TaskResult と DayRecordView は records.py にある。版の違う records.json は読まずに `records.other-version-<日時>.json` で残す（設計も直した。self-check 3.2 はこれと `*.corrupt-*.json` を探す）。試しは `NullRecordBook.from_store(store)`（読むだけ）を使う。書く側の共通の型はまだない
- Scheduler: `wake_time(day, tz)`（tz は now.tzinfo）。now はタイムゾーン付きでないと ValueError。`_due_tasks(now, records)` は今始められるタスクを設定の順に全部返す（cut_in で使う）。起床時刻より前の時刻のタスクは、後ろの続きも予告も次の予定も含めて落とす。前のタスクが今日に当てはまらないと続きは落ちる
- おやすみの時間: 寝るタスクのない種類の日は「起床時刻より前」だけがおやすみ（平日だけ寝るタスクがあると、土曜の夜は 0 時に急に静かになる。手順書で寝るタスクは毎日にするよう勧める）。寝る時刻より後の割り込めるタスクは寝るタスクに割り込めるが、寝るタスクが中断で終わるとおやすみに入るので、その後のタスクは始まらない（3.3 の確かめの流れはおやすみの判定を先に見る）
- 進み方: 準備の言葉があるタスクは 4.2 に従い「準備 → 押されるまで待つ → 声かけ」の順。`Texts(call_name)` は runner.py にある（3.3 は `Texts(config.call_name)` で作る）。台本の入出力は `tests/features/routine/scripted_io.py`（ScriptedIO・ScriptedHooks）。TaskRunner.run は stop を受けないので、準備の待ち（上限なし）やあとでの 30 分の間に機能を止めると戻らない。3.3 で、止める旗を見て抜ける口（例: hooks で止める知らせを返す）を足し、止めると速やかに戻ることをテストする（3.3 で解決: TaskHooks.should_stop と TaskStopped）
- LeaseIO: ダンスの間は偽の時計が約 1.5 秒進む（ダンスのスレッドが Clock.sleep を呼ぶ）。偽の時計で LeaseIO を動かすテストはその分を見込む。走行の口は DRIVE を借りているときだけ渡す
- self-check: だめは「祝日を判定できない」「記録を書けない」だけ。版を戻しても直らないこと（時間帯の重なり・記録を読めない・壊れた記録が残っている）は、よいに理由を添える（配置の道具はだめが 1 つでもあると版を戻すため。設計も直した）。手順書（3.5）に、残った記録の消し方と時間帯の直し方を書く。ROUTINE_CHECKS を 3.3 の申告の checks に渡す
- 確かめの流れ: 止めると TaskRunner は TaskStopped を投げ、結果は記録しない。割り込んだタスクは同じ確かめの中で同じリースで始める。続きのタスクは次の確かめで始まる。タスクの途中の思いがけない例外は記録されないので、1 秒ごとに同じタスクが始め直されうる（3.4 で解決: 中断として記録する。ResourceBusy と on_preempt のテストも 3.4 で足した）
- おやすみ: 寝るタスクの資源を持ったまま「ｵﾔｽﾐ」を見せて静かな状態を求め、その後に資源を返す（待機画面が光らない）。起動の直後（`_just_booted`）のおやすみは表示も首もなし。タスクの途中の思いがけない例外は中断として記録する。寝るタスクに割り込んだタスクは始めない
- 登録: エントリーポイントを足したので、本物の機能の発見を使う既存のテストに日課が入る（test_registry と test_cli_selfcheck を直した）。手順書 docs/routine.md の 6 章は試しのコマンド（4.1）の決まり（75・1・2・0、--fast は 10 秒と 30 秒）を書いてあるので、4.1 はそれに合わせる
- 試しのコマンド: 本物の SystemClock で動くので、テストは FAST_TIMINGS と SLEEP_SHOW_S を差し替える（約 5 秒）。SIGTERM では片付けを通らない（Ctrl+C は通る）。試しの機能の __init__ で例外が出ると終わりを待ち続ける（起こりにくい）
- 通しのテスト: Kit と補助は tests/features/routine/routine_kit.py、kit の準備は conftest.py。日付をまたぐ予告は寝るタスクのない設定でしか起きない（寝るタスクがあると 6.4・6.5 で予告も 0 時台のタスクも出ない）
